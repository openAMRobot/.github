## Method

1. Register check, from this checkout, once per repository:
   `python3 tools/check_decisions.py --decisions decisions.yaml --maintainers maintainers.yaml --root <checkout> --repository <name>`
2. Reading review of README and docs pages, package READMEs, configuration and parameter files, URDF/xacro comments, launch files, firmware and hardware docs, against every register decision area and the UC1 requirements each repository implements or documents.
3. Open PRs of every repository were fetched (`refs/pull/<N>/head`) and diffed, so each finding records whether an open PR already changes the same lines.
4. Classes: A = retired value presented as current (text); B = imprecise or incomplete description of a current decision; C = implementation differs (code, config, geometry, parameter); D = conflict between sources (register, P-03, Use Case 1 baseline, or between repositories); E = missing coverage.
5. "fixable" means class A or B, pure text, outside the out-of-scope list (safety logic or safety-path wording that changes a function, message/service/action definitions, topic names, launch argument names, configuration IDs, URDF/xacro geometry, joint origins, masses, dependency pins, CI thresholds and allowlists) and outside the safety paths in maintainers.yaml.
6. Historical text (dated logs, changelogs, evidence records, lines labelled superseded, legacy, historical or Gate A) is kept; only text presenting a retired value as current is a finding.
7. Personal names, prices, contact data and internal links found in repositories are reported here without reproducing them.
